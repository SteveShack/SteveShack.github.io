Protect the Core. Survive the Waves.

Poly Defense is an ambitious solo project combining the strategic planning of Tower Defense with the engaging action of a First-Person Shooter. Set in a Sci-Fi universe involving dimensional travel, players must secure giant Cores while surviving against relentless waves of enemies.

This project serves as my ultimate playground for mastering Unreal Engine 5. From engineering complex AI behaviors to balancing resource economies and hybrid game loops, I am building every system entirely from scratch to push the boundaries of my technical design capabilities.

Technical Design Deep Dives

  • Enemy AI & Pathing
  • Tower Architecture
  • UI/UX Iteration

Problem: Enemies navigating a complex TD environment were getting stuck on walls using standard navmesh seeking. When moved to strict spline-based pathing, they felt too robotic, and applying damage on event tick made combat feel unfair.

Solution: Engineered a hybrid navigation system. Splines handle macro-navigation toward the core, while a custom Blackboard and Behavior Tree allow enemies to dynamically break from the spline to engage the player and towers.

Reasoning: The game needed reliable pathing to satisfy Tower Defense mechanics, but required dynamic, reactive combat for the FPS side. Tying damage to attack animations rather than event ticks made combat fair and readable.

What I Learned: Iteration is crucial for game feel. Solving a technical pathing issue created a design issue (robotic movement), requiring a behavioral solution to make enemies feel alive and fun to fight.

Problem: Developing multiple tower types with unique behaviors (single-target, AoE, multi-hit) without creating messy, redundant code or convoluted targeting logic.

Solution: Designed an Object-Oriented parent-child class hierarchy. The parent handles core placement logic (valid/invalid zones) and basic targeting. Child classes handle unique projectile logic (destroying arrows, multi-hit zaps, AoE blasts).

Reasoning: An object-oriented approach allows for rapid prototyping, easy balancing, and seamless addition of new towers without rebuilding foundational systems.

What I Learned: Building a modular foundation early saves countless hours during balancing, allowing the focus to remain on how projectiles feel rather than how the tower detects enemies.

[Insert GIF: Showcasing different tower projectile types]

Problem: The dual-nature of a TD/FPS requires fast access to building tools and weapons. Initial UI designs (split left/right screens) were visually cluttered and ineffective during fast-paced gameplay.

Solution: Consolidated the UI into a unified bottom-screen tab system to switch between towers and guns. (Currently prototyping a radial wheel menu for even faster selection).

Reasoning: Screen real estate is premium in an FPS. Centralizing the build menu reduces eye-travel, keeping the player focused on the action while accessing tactical options.

What I Learned: UI in a hybrid game cannot just be a port of standard genre UI; it must be custom-built to serve the immediate pacing and cognitive load of the game.
